**Nota sobre `--color-border-default`:** Border #E6E6E6 sobre white tem contraste 1.25:1 · falha WCAG 1.4.11 (3:1 mínimo pra UI components). **Mitigação:** o foco em inputs é representado por `--color-border-focus` (5.38:1) · usuário sempre vê border claro quando está digitando. Border default não-focus serve só como divisor visual sutil, não como indicador funcional. Aceito como decisão de design.

## Focus visible

Todos elementos interativos do DS têm focus state visível via `:focus-visible`:

| Component | Focus indicator |
|---|---|
| `.ds-btn` (qualquer variant) | `--shadow-focus-blue` (3px blue glow) |
| `.ds-btn-danger` | `--shadow-focus-error` (3px red glow) |
| `.ds-link` | outline 2px blue + offset 2px |
| `.ds-input` / `.ds-select` / `.ds-textarea` | border `--color-border-focus` + `--shadow-focus-blue` |
| `.ds-check input` | border focus + ring |
| `.odex-select-trigger` | border focus + ring |
| `.odex-select-option` | inset border focus + bg hover |
| `.ds-menu-item` | inset border focus + bg hover |
| `.auth-back` | bg + color + shadow focus |
| `.auth-submit` | shadow CTA + shadow focus combinados |
| `.auth-secondary` | border focus + shadow |
| `.auth-link` | outline 2px blue |

Base reset (`ds/base/reset.css`) define fallback `:focus-visible { outline: 2px solid var(--color-border-focus); }` pra elementos não-listados.

## Reduced motion

`ds/base/reset.css` inclui:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

Usuário com OS-level "reduce motion" não vê transitions/animations · all `--motion-*` virtually instantâneos.

## ARIA pattern por molecule

### `.odex-select`

Construído via `applyOdexSelects()`. Markup gerado:

```html
<button class="odex-select-trigger"
        aria-haspopup="listbox"
        aria-expanded="true|false">
  <span class="odex-select-label">...</span>
</button>
<div class="odex-select-menu" role="listbox">
  <button class="odex-select-option" role="option" data-value="...">
    <span>label</span>
    <span class="odex-select-option-check">✓</span>
  </button>
  ...
</div>
```

| ARIA | Status |
|---|---|
| `aria-haspopup="listbox"` no trigger | ✅ |
| `aria-expanded="true\|false"` | ✅ |
| `role="listbox"` no menu | ✅ |
| `role="option"` em cada item | ✅ |
| `aria-selected="true"` no item ativo | ❌ TODO C.8.1 |
| `aria-activedescendant` no trigger | ❌ TODO C.8.1 |
| Keyboard nav (↑/↓/Enter/Esc) | ❌ TODO C.8.1 |

### `.ds-menu`

Manual markup. Recomendado:

```html
<div class="ds-menu">
  <button class="ds-menu-trigger"
          aria-haspopup="menu"
          aria-expanded="false">...</button>
  <div class="ds-menu-popover" role="menu">
    <button class="ds-menu-item" role="menuitem"
            aria-current="true">...</button>
  </div>
</div>
```

| ARIA | Status |
|---|---|
| `aria-haspopup="menu"` | ✅ doc |
| `aria-expanded` | ✅ doc |
| `role="menu"` | ✅ doc |
| `role="menuitem"` | ✅ doc |
| `aria-current="true"` selected | ✅ doc |
| Keyboard nav | ❌ TODO C.8.1 |
| Focus trap quando aberto | ❌ TODO C.8.1 |

## Skip links

App não tem skip links ainda. Quando feature topbar/sidebar for extraída (Phase C.10+), adicionar:

```html
<a href="#main-content" class="ds-skip-link">Pular para conteúdo principal</a>
```

Com classe `.ds-skip-link` (criar atom em C.10+) que esconde visualmente até receber `:focus`.

## Touch targets

Recomendação WCAG 2.5.5: 44×44 CSS pixels mínimo.

| Component | Tamanho | Pass? |
|---|---|---|
| `.ds-btn` default | 42×~auto wide | ⚠ borderline (42 vs 44) · OK por padding lateral |
| `.ds-btn-sm` | 32×auto | ❌ Use só pra contextos densos (filtros toolbar) |
| `.ds-btn-lg` | 48×auto | ✅ |
| `.ds-input` | 42×100% | ⚠ borderline |
| `.ds-check input` | 18×18 visual, hit area `<label>` envolve | ✅ via label wrapper |
| `.auth-submit` | 48×100% | ✅ |
| `.odex-select-trigger` | 46×100% | ✅ |

Mitigação: usuários mobile com toques grandes acessam o `<label>` envolvendo o checkbox, o `<a>` envolvendo o link, etc. Native HTML elements têm hit area que extrapola o visual.

## Como auditar contrast localmente

```bash
node -e "
const lin = c => c <= 0.03928 ? c/12.92 : Math.pow((c+0.055)/1.055, 2.4);
const lum = hex => {
  const r = parseInt(hex.slice(1,3),16)/255, g = parseInt(hex.slice(3,5),16)/255, b = parseInt(hex.slice(5,7),16)/255;
  return 0.2126*lin(r) + 0.7152*lin(g) + 0.0722*lin(b);
};
const con = (a,b) => { const la=lum(a), lb=lum(b); return ((Math.max(la,lb)+0.05)/(Math.min(la,lb)+0.05)).toFixed(2); };
console.log(con('#FOREGROUND', '#BACKGROUND') + ':1');
"
```

Ou use ferramentas:
- [WebAIM Contrast Checker](https://webaim.org/resources/contrastchecker/)
- Chrome DevTools (inspect element → contrast ratio in color picker)
- axe DevTools extension

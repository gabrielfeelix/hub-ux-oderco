Z-index scale

Use intent (--z-dropdown, --z-modal) em vez de números mágicos. Camadas pensadas pra evitar guerra de z-index.

--z-base 0 Default · sem stacking --z-rise 1 Pequeno lift · cards hover --z-dropdown 100 Dropdowns, menus --z-sticky 200 Sticky elements, sidebar fixa --z-overlay 300 Modal overlay (backdrop) --z-modal 310 Modal content (acima overlay) --z-popover 400 Popovers, tooltips · acima modal --z-toast 500 Toasts · top of stack --z-loader 9999 Full-screen loader 
/* uso típico */
.modal-overlay {
  z-index: var(--z-overlay);
}
.dropdown-menu {
  z-index: var(--z-dropdown);
}

Breakpoints

Escala canônica. CSS vars não funcionam em @media queries · use os valores literais correspondentes.

--bp-sm 600px Mobile · phones --bp-md 768px Tablet --bp-lg 960px Small desktop --bp-xl 1100px Desktop --bp-xxl 1280px Wide desktop
Limitação CSS: media queries não aceitam var(). Use literais matching a escala.
/* uso correto · literais matching --bp-* */
@media (max-width: 600px) { ... }   /* --bp-sm */
@media (max-width: 768px) { ... }   /* --bp-md */
@media (max-width: 960px) { ... }   /* --bp-lg */
@media (max-width: 1100px) { ... }  /* --bp-xl */

Architecture · CSS @layer

DS usa cascade layers explícitas via @layer. Elimina guerra de specificity e torna ordem de override determinística.

1reset base HTML resets 2tokens :root CSS variables 3atoms .ds-* primitives 4molecules .odex-select, .ds-menu 5features .auth-*, .mk-* (composition) 6legacy compat overrides pré-DS 7utilities .text-center, .mt-4 (futuro)
Regra: layer mais alta vence layer mais baixa, independente de specificity. Estilos sem @layer (unlayered) sempre vencem os layered. 
/* ds/index.css */
@layer reset, tokens, atoms, molecules,
       features, legacy, utilities;

@import url('./tokens/tokens.css')
  layer(tokens);
@import url('./atoms/index.css')
  layer(atoms);
...

/* features/auth/auth.css */
@layer features {
  .auth-shell { ... }
}

Semantic tokens · intro

Tokens semânticos são aliases por intenção. Em vez de usar primitivas direto (--blue, --red), componentes referenciam o intent (--color-action-primary-bg, --color-feedback-error-strong). Isso destrava theming/dark-mode/brand-variant trocando só este bloco.

Regra: componentes do DS (atoms, molecules) devem usar semantic tokens. Primitivas (--blue, --navy, --red) ficam pra casos especiais ou para o próprio bloco semantic.
Padrão de naming: --color-<categoria>-<elemento>-<estado> · categorias: action / surface / text / border / feedback / status.
Antes (primitive direto) 
.ds-btn-primary {
  background: var(--blue);
  color: var(--white);
}
.ds-btn-primary:hover {
  background: var(--blue-hover);
}
Depois (semantic) 
.ds-btn-primary {
  background: var(--color-action-primary-bg);
  color: var(--color-action-primary-fg);
}
.ds-btn-primary:hover {
  background: var(--color-action-primary-bg-hover);
}
